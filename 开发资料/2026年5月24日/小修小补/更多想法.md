## 设置页路径自动匹配栏设计

目标：在设置界面填写“日记保存目录”和“日记模板文件”时，用户既可以手动输入，也可以从自动匹配栏里点选 vault 内已有路径，减少记完整路径的成本。

设计思路：

1. 使用 Obsidian 原生 `AbstractInputSuggest` 给现有输入框增加候选弹层，不新增设置字段，也不改变当前数据结构。
2. “日记保存目录”只匹配文件夹路径，候选来源为 vault 内已有文件夹；用户仍然可以手动输入尚不存在的目录，后续保存日记时继续按现有逻辑自动创建。
3. “日记模板文件”只匹配 Markdown 文件路径，候选来源为 vault 内 `.md` 文件，选择后直接写入 `templateFilePath`。
4. 匹配规则采用“路径前缀优先，其次包含匹配”，并限制候选数量，避免 vault 文件很多时弹层过长。
5. 点选候选后立即更新输入框并保存设置；手动输入仍走原来的保存流程和路径安全校验。

验收标准：

1. 设置页两个输入框都保留手动输入能力。
2. 输入部分路径时能出现可点选候选。
3. 日记保存目录只出现文件夹，模板文件只出现 Markdown 文件。
4. 点选候选后重新打开设置页，路径仍然保留。
5. 不影响默认心情、视图模式、Memory Board 等其他设置项。

## 日记模板文件路径候选补充

本次实现中，“日记模板文件”使用独立的 Markdown 文件候选逻辑，而不是复用文件夹候选：

1. 候选来源限定为 `app.vault.getMarkdownFiles()`，避免用户误选图片、PDF 或文件夹。
2. 候选显示完整 vault 相对路径，例如 `模板文件夹/日记模板.md`。
3. 用户点选候选后，输入框立即更新为该路径，并保存到 `templateFilePath`。
4. 用户仍可手动输入路径；如果文件不存在，后续保存日记时沿用现有提示逻辑，回退到内置模板。
5. 此功能只改善设置页输入体验，不改变模板读取规则，也不改变日记保存数据结构。
