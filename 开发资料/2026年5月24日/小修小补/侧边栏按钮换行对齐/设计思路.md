# 侧边栏按钮换行对齐设计思路

## 问题

侧边栏月视图顶部的“日历 / 今天 / 快速记录”按钮在宽度足够时右对齐是合理的。但侧边栏较窄、按钮发生换行后，继续右对齐会让第二行按钮靠右悬空，视觉上不协调。

## 原因

`.Everyday-header-actions` 默认使用 `justify-content: flex-end`。现有移动端样式只把 Memory Board 的 `.Everyday-memory-board-actions` 改成左对齐，没有覆盖侧边栏月视图的 `.Everyday-header-actions`。

## 实现策略

1. 保留桌面或宽侧边栏下的右对齐布局。
2. 在现有 `@media (max-width: 520px)` 窄宽规则中加入 `.Everyday-header-actions`。
3. 窄宽时统一设置：
   - `flex: 1 1 auto`
   - `flex-wrap: wrap`
   - `justify-content: flex-start`
   - `width: 100%`
4. 不修改按钮 DOM、不新增设置项，也不影响日记列表、日历格和 Memory Board 的现有布局。

## 影响范围

- 只修改 `styles.css`。
- 仅影响窄侧边栏或窄屏下月视图顶部操作按钮换行后的对齐方式。
- 宽度足够时仍保持原来的右对齐设计。

## 回退说明

曾尝试改为 container query 按侧边栏容器宽度触发，但该修复在人工验证中有问题，已按要求回退到上一版 `@media` 方案。

## 试验方案 B

新的试验方向不再把三个操作按钮改成左对齐，而是保持它们右对齐；当头部检测到操作按钮已经换到下一行时，给 header 增加 `is-actions-wrapped` 状态，并把上方的月份切换区域也改为右对齐。

实现方式：

1. `MonthMemoryView` 在渲染 header 后使用 `ResizeObserver` 观察 header 宽度变化。
2. 如果 `.Everyday-header-actions.offsetTop > .Everyday-nav.offsetTop`，说明操作按钮已经换行。
3. 换行时给 `.Everyday-header` 添加 `is-actions-wrapped`。
4. CSS 使用 `.Everyday-header.is-actions-wrapped .Everyday-nav { justify-content: flex-end; }`，让月份切换和操作按钮在换行后同向右对齐。
5. 视图关闭或重新渲染时断开旧 observer，避免重复监听。
